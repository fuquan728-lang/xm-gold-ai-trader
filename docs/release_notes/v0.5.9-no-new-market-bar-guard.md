# v0.5.9 No-New-Market-Bar Guard

Narrow read-only guard that detects when `latest_closed_bar_time` has not
advanced, preventing duplicate/cached bars from being counted as forward
evidence.

## Scope

- Extended `_collect_forward_window_stats()` to track bar-time progression
  across enriched journals.
- Added `market_bar_guard` section to `forward_sample_collection_plan.window`.
- No changes to strategy, risk, safety, order routing, or AI annotation.

## Problem

During weekend/closed-market periods, `run_dry_observation_campaign.py` can
produce journals where `latest_closed_bar_time` is the same as a previous
journal — a cached/duplicate bar from Friday close. Without explicit detection,
these journals could be visually confused with new forward evidence, even
though `unique_closed_bars` correctly excludes the duplicate.

## Solution

In `_collect_forward_window_stats()`:

1. Sort enriched journals chronologically by `timestamp_utc`.
2. Compare each journal's `latest_closed_bar_time` against the previous one.
3. Journals where bar time did not advance are counted as `NO_NEW_MARKET_BAR`.
4. Report `no_new_bar_journal_count`, `market_advancing`, and
   `weekend_or_market_closed_possible`.

The guard does NOT change `enriched_closed_bar_count` (which already uses
`set` dedup). It adds explicit visibility into whether the market is
producing fresh bars.

## Current Detection

| Field | Value | Meaning |
|-------|-------|---------|
| `no_new_bar_journal_count` | 3 | 3 journals share a bar time with previous |
| `market_advancing` | true | Multiple unique bars exist historically |
| `weekend_or_market_closed_possible` | false | Historical bars still show advance pattern |
| `campaigns_without_bar_advance` | 2 | Two weekend campaigns produced no new bar |

## Safety Guarantees

- `orders_sent: 0`
- `order_check_called: false`
- `order_send_called: false`
- No strategy, risk, threshold, safety, order routing, or AI annotation changes.
- This is a read-only metrics enhancement only.
