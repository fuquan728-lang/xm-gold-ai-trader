# v0.5.6 Forward Sample Collection Plan

This checkpoint converts the v0.5.5 forward evidence gates into an executable
read-only sampling plan with progress tracking. It does not change any
production strategy, risk setting, safety gate, order routing, or AI annotation
behavior.

## Scope

- Extended `scripts/strategy_hypothesis_lab.py --json` with top-level
  `forward_sample_collection_plan`.
- Added progress tracking fields: enriched closed-bar count, final dry-run
  SIGNAL count, diagnostics coverage percentage, and gate status.
- Added recommended sampling command and sampling cadence rules.
- Added pytest coverage proving the plan exists, defines all required tracking

This is a planning checkpoint only. It does not change production strategy,

## 1. Progress Tracking

The plan tracks three forward evidence gates defined in v0.5.5:

| Gate | Target | Tracking Field |
|------|--------|----------------|
| Enriched closed bars | `>= 500` | `progress.enriched_closed_bars` |
| Final dry-run SIGNALs | `>= 5` | `progress.final_dry_run_signals` |
| Diagnostics coverage | `>= 95%` | `progress.diagnostics_coverage` |

Each tracking field reports:

- `current` — current observed count
- `required` — target threshold
- `remaining` — how many more observations needed
- `met` — boolean indicating if the gate is satisfied

The top-level `forward_evidence_gates_met` field is `true` only when all three
gates are met.

Progress defaults to zero — gates default to unmet. No gate is treated as
passed by accident.

## 2. Sampling Command

Recommended read-only dry-run observation command:

```
python scripts\run_dry_observation_campaign.py --symbol GOLD_ --timeframe M15 --interval-seconds 60 --max-iterations <N> --bar-close-only --json
```

Parameters:

- `--symbol GOLD_` — always GOLD_
- `--timeframe M15` — always M15 for forward evidence collection
- `--interval-seconds 60` — sample at 60-second intervals
- `--max-iterations <N>` — bounded run only, replace `<N>` with actual count
- `--bar-close-only` — never sample on incomplete bars
- `--json` — output structured JSON for automated processing

## 3. Sampling Cadence

Required rules:

1. **Bounded runs only** — always use `--max-iterations` to limit the campaign.
2. **Bar-close-only** — never sample on incomplete bars.
3. **Check progress after every run** — review enriched bar count, signal count,
   and coverage before committing next iteration.
4. **Never change `allow_order_send`** — keep
   `execution.allow_order_send: false` at all times.
5. **If a campaign run fails** or produces malformed journals, investigate
   before continuing.

Recommended review cadence:

- After every **100 enriched closed bars**: verify diagnostics coverage
  `>= 95%`.
- After every **5 dry-run SIGNAL observations**: verify journal quality and
  signal forensics.
- Before declaring gates met: run full pipeline verification (`pytest` + all
  `--json` checks).

## 4. What Gates Met Unlocks

When all three forward evidence gates are met:

- v0.6 offline parameter-candidate research may begin.
- Production strategy changes remain **blocked**.
- Live order enablement remains **blocked**.
- All safety boundaries remain active.

Next steps after gates pass:

- Run out-of-sample historical split with candidate and feasibility counts
  separated.
- Report minimum-lot feasibility under realistic account balance and
  risk-per-trade assumptions.
- Measure spread and ATR regime sensitivity for feasible candidates.
- Begin MAE/MFE and drawdown proxy analysis when sufficient history is
  available.
- Maintain chronological train/test split — never select parameters on the test
  split.
