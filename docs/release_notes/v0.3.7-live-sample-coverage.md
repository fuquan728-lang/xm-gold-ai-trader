# v0.3.7 Live Sample Coverage

Release checkpoint for `xm-gold-ai-trader`, focused on making live sample
coverage status explicit while preserving the v0.3.6 read-only research safety
baseline.

This checkpoint does not add AI model trading, does not call `order_check`, does
not call `order_send`, and does not enable order sending in the default
configuration.

## Scope

- Improved live sample coverage reporting in the dry-run observation quality
  check.
- Improved live sample coverage reporting in the live-vs-historical signal rate
  comparison.
- Lifted live sample coverage details into the top-level
  `research_pipeline_verify.py --json` output.
- Kept live sample warnings visible. The pipeline does not convert low sample
  coverage to PASS by hiding `UNIQUE_CLOSED_BARS_BELOW_MINIMUM` or
  `INSUFFICIENT_LIVE_SAMPLE`.

## Live Sample Source

The live sample coverage source is:

- Source name: `dry_run_signal_journals`
- Source path: `logs/dry_run_signals`
- Source glob: `logs/dry_run_signals/*.json`

Coverage is counted from valid live dry-run signal journals, deduplicated by the
closed-bar identity used by the dry-run observation quality logic:

- symbol
- timeframe
- campaign id
- latest closed bar time

Campaign metadata from `logs/dry_run_campaigns` is used for supporting poll and
duplicate-skip diagnostics, but the coverage count itself comes from unique
closed-bar dry-run signal journals.

## Current Status

- `python scripts\research_pipeline_verify.py --json` may return `WARN` while
  live sample coverage is below the configured minimum.
- `UNIQUE_CLOSED_BARS_BELOW_MINIMUM` means the observation quality gate counted
  fewer unique closed bars than `--min-unique-bars`.
- `INSUFFICIENT_LIVE_SAMPLE` means the live-vs-historical expectation check
  counted fewer live bars than `--min-live-bars`.
- These warnings are research-quality warnings, not safety failures.

## Safety Status

- Default `configs/xm_gold_ai_trader.demo.yaml` remains
  `execution.allow_order_send: false`.
- Research scripts still report `orders_sent: 0`.
- Research scripts still report `order_check_called: false`.
- Research scripts still report `order_send_called: false`.
- AI annotation and analysis remain read-only commentary.
- No Phase 3 research/AI script should contain direct `order_check(` or
  `order_send(` calls.

## Verification Commands

```powershell
python -m pytest
python scripts\research_pipeline_verify.py --json
python scripts\evaluate_dry_run_observation_quality.py --json
python scripts\compare_live_vs_historical_signal_rate.py --json
```

Expected behavior:

- `pytest` passes.
- `research_pipeline_verify.py` returns PASS if live sample coverage is
  sufficient and no other warnings are present.
- If coverage remains insufficient, `research_pipeline_verify.py` returns WARN
  with explicit live sample coverage fields and exact WARN reasons.
- Any order activity, `order_check`, `order_send`, or forbidden AI trading
  content remains a BLOCK condition.
