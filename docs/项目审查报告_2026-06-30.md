## 三、P0 严重问题

### P0-1: API Key 明文存在于 `.env` 文件中

```
文件: .env
行: 8
内容: DEEPSEEK_API_KEY=<REDACTED>
```

**风险**: 如果该仓库曾以任何形式共享或推送，密钥已泄露。`.gitignore` 虽包含 `.env` 规则，但文件系统中仍存有真实密钥。
**修复**: 立即轮换密钥，并确保密钥仅通过环境变量注入，不在项目文件中存储。

### P0-2: 保证金危机处理——四个关键执行函数均为空存根

```
文件: core/margin_crisis_handler.py
行 718-755: _close_small_positions() / _close_losing_positions() /
            _close_all_positions() / _stop_all_trading() / 
            _apply_risk_adjustments() / _send_user_notifications()
状态: 全部为注释占位，无实际执行代码
```

**风险**: 当保证金危机触发时，系统会记录警告但**不会执行任何保护性操作**。账户可能在危机中持续亏损而没有任何自动干预。
**修复**: 将 `margin_crisis_handler` 与 `trade_executor` 和 `risk_manager` 建立连接。

### P0-3: `async_optimizer.py` 中 asyncio/threading 锁混合使用

```
文件: core/async_optimizer.py
行 589: self.lock = threading.RLock()
行 600: async def record_operation(...)
```

**风险**: `PerformanceMonitor` 使用 `threading.RLock()` 但被 `async def` 方法调用。在 asyncio 事件循环中混用线程锁可能导致死锁——当协程持有锁时被挂起，其他协程将永久阻塞。
**修复**: 替换为 `asyncio.Lock()`。

## 四、P1 高优先级问题

### P1-1: MQL5 EA 代码高度重复（5个变体）

| EA 文件 | 行数 | 状态 |
|---------|------|------|
| AI_Trader_V3.2_Integrated.mq5 | 1200+ | 最新版，Socket+File |
| AI_Trader_Integrated.mq5 | 1594 | File模式旧版 |
| AI_Trader_Integrated_Socket.mq5 | ~1200 | Socket模式 |
| AI_Trader_Integrated_Optimized.mq5 | 852 | 精简版 |
| AI_Trader_V2.1_Safe.mq5 | ~800 | 更早版本 |

**问题**: 5个EA文件共享约60%代码（指标初始化、面板创建、追踪止损、文件I/O、响应解析），但没有共享的 `.mqh` 头文件。任何 bug 修复需要在5个文件中重复操作。
**修复**: 提取共享逻辑到 `Include/AI_Trader_Common.mqh`，各EA变体仅保留差异化逻辑。

### P1-2: `trade_executor.py` 硬编码模拟价格

```python
# core/trade_executor.py:429-434
price_map = {
    "EURUSD": 1.0850,
    "GBPUSD": 1.2650,
    "USDJPY": 151.50,
    "GOLD": 2350.0,       # 黄金当前实际约3250+
    "XAUUSD": 2350.0
}
```

**风险**: 如果 `MT5TradingInterface.get_market_price()` 在实盘场景被调用，将使用严重过时的价格（黄金差约900美元），导致错误的订单执行和风险评估。
**修复**: 增加明显的环境检测和硬阻止，确保模拟接口不会在实盘中执行。

### P1-3: `risk_manager.py` 中 `trade_history` 无限增长

```python
# core/risk_manager.py:156
self.trade_history: List[Dict[str, Any]] = []  # 无上限
```

**风险**: 长时间运行后内存持续增长，每个交易记录包含完整字典数据。按日均10笔交易计算，一年后将积累3650条记录。
**修复**: 设置上限（如最近1000条），超出时自动裁剪。

### P1-4: 核心AI决策管道无单元测试

```
测试状态:
- tests/legacy/test_mql5_data.py    ✓ 存在
- tests/legacy/test_web.py          ✓ 存在
- core/ai_engine.py                  ✗ 无测试
- core/risk_manager.py               ✗ 无测试
- core/validator.py                  ✗ 无测试
- core/cache.py                      ✗ 无测试
- core/async_optimizer.py            ✗ 无测试
```

**风险**: AI管道（提示构建→API调用→JSON解析→风险验证→信号输出）任何环节的回归都可能影响交易决策质量。
**修复**: 至少为 `ai_engine.extract_json()`、`risk_manager.assess_trade_risk()`、`validator.validate_signal()` 添加单元测试。

### P1-5: 主服务 `service_status` 无锁保护的竞态条件

```python
# mt5_ai_service.py:59-66
service_status = {
    'running': False,
    'mode': 'auto',
    ...
}
# 被多个线程读写，无锁保护
```

**风险**: 在Socket模式下多连接并发时，`service_status` 字典可能被并发修改导致数据不一致或 KeyError。
**修复**: 使用 `threading.RLock()` 包装读写操作。

## 五、P2 中优先级问题

### P2-1: Pip 与 MT5 Point 单位混淆

- `mt5_ai_service.py` 的 `_calculate_dynamic_sl_tp` 中：`1 pip = 10 * _Point`
- `risk_manager.py` 的 `_get_point_value` 对黄金返回 `1.0`（per point 而非 per pip）
- 对于 XAUUSD（黄金），1 pip = 10 points = $1（1手），但系统中两者未统一

### P2-2: HTTP Client 单例非线程安全

```python
# core/http_client.py:91
def get_http_client():
    global _http_client
    if _http_client is None:  # 竞态窗口
        _http_client = HTTPClient(...)
```

### P2-3: 日志格式不一致

项目中使用三种日志格式混合：f-string、`%`-style、`.format()` 共存于同一模块。

### P2-4: 类型提示不完整

`trade_executor.py`、`file_handler.py`、`websocket_handler.py` 中大量函数缺少返回类型标注。

### P2-5: MQL5 EA 手动JSON构建存在转义风险

EA使用字符串拼接（`StringConcatenate`）构建JSON，如果持仓注释包含引号或特殊字符会导致JSON解析失败。

### P2-6: 配置系统 `_set_defaults()` 为空存根

```python
# core/config.py
def _set_defaults(self):
    pass  # 未实现
```

### P2-7: `weight_optimizer.py` 文件写入无锁保护

多线程同时保存权重文件可能导致数据损坏。

## 六、P3 战略优化

### P3-1: PPO 强化学习管道未完成
`datastore.py` 定义了PPO体验回放表，但项目中无实际训练循环。这是有价值但未完成的架构规划。

AI提示词将市场价格发送给DeepSeek，但模型无法访问实时数据——本质上在做模式匹配而非真正的市场分析。可考虑增加实时新闻/经济数据源。

### P3-3: 跨品种验证缺失
所有测试和优化仅针对 XAUUSD/GOLD，未验证策略在其他品种上的表现。

### P3-4: 回测系统待建设
缺少专业的回测框架来验证AI策略的历史表现和参数优化。

## 八、策略层面改进建议

### 8.1 置信度校准问题
当前AI返回的置信度是LLM自我评估，未经过统计校准。建议：记录AI预测置信度 vs 实际结果的校准曲线，使用 Platt Scaling 或 Isotonic Regression 进行后校准。

### 8.2 决策频率优化
当前每个Tick都可能触发AI分析（通过File/Socket轮询），高频决策消耗API额度且可能引入噪声。建议：设置最小决策间隔（如5分钟），结合市场波动率动态调整。

### 8.3 对冲策略
当前只有单向持仓逻辑，未考虑对冲场景。对于黄金这种高波动品种，应考虑在一定条件下允许对冲持仓。

### 8.4 时间衰减
AI提示词中虽有会话时间但未考虑市场时段效应。亚洲盘/欧洲盘/美洲盘波动特征差异大，应纳入决策权重调整。
