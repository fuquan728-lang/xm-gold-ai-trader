## 2. 详细实施内容

### 2.1 Socket服务器集成

**实施内容**:
- 创建集成版AI服务: `ai_service_integrated.py`
- 实现三种通信模式: `socket`、`file`、`auto`
- 设计ModeManager类管理模式切换
- 实现AISocketHandler处理Socket请求
- 保持与原有文件模式的向后兼容性

**技术特点**:
- 双模式运行架构，支持热切换
- 动态模式选择，根据可用性自动优化
- 性能监控和统计功能
- 并发连接管理（最大10个并发连接）

### 2.2 MQ5文件改造

**实施内容**:
- 创建Socket版MQL5 EA: `AI_Trader_Integrated_Socket.mq5`
- 彻底替换文件通信机制为Socket通信
- 实现带重试机制的Socket请求函数
- 添加模式切换和故障转移逻辑

**核心函数**:
- `SocketRequest()`: 基础Socket请求
- `SocketRequestWithRetry()`: 带重试的Socket请求
- `DetermineCommunicationMode()`: 确定通信模式
- `SendAIRequest()`: 统一的AI请求发送

### 2.3 配置管理系统

**实施内容**:
- 扩展`config.py`添加通信模式配置
- 更新`.env.example`和`.env`配置文件
- 实现配置验证和错误提示
- 创建动态配置更新机制

**新增配置项**:
```env
# 通信模式配置
COMMUNICATION_MODE=auto          # socket, file, auto
SOCKET_HOST=127.0.0.1            # Socket服务器地址
SOCKET_PORT=8080                 # Socket服务器端口
SOCKET_TIMEOUT=5.0               # Socket连接超时时间
MAX_CONCURRENT_CONNECTIONS=10    # 最大并发连接数
RETRY_BACKOFF_FACTOR=2.0         # 重试退避因子
FAILOVER_THRESHOLD=3             # 故障转移阈值
AUTO_SWITCH_THRESHOLD=3          # 自动切换阈值
FILE_MODE_PATH=                  # 文件模式路径
```

### 2.4 错误处理与可靠性保障

**实施内容**:
- 创建ErrorHandler类提供全面错误处理
- 实现智能重试机制（指数退避策略）
- 开发结构化错误日志记录系统
- 实现服务降级和故障转移方案

**错误分类**:
- Socket连接异常（连接拒绝、超时、重置）

**可靠性特性**:

### 4.2 通信接口规范

**请求格式 (JSON)**:
```json
{
  "symbol": "XAUUSD",
  "bid": 2000.50,
  "ask": 2000.55,
  "time": 1745000000,
  "history": [...],
  "indicators": {...}
}
```

**响应格式 (JSON)**:
```json
{
  "action": "BUY|SELL|HOLD",
  "confidence": 0.85,
  "reason": "技术分析说明",
  "timestamp": 1745000001
}
```

**错误响应格式**:
```json
{
  "error": true,
  "message": "错误描述",
  "code": "ERROR_CODE",
  "timestamp": 1745000001
}
```

### 4.3 通信模式说明

**1. Socket模式 (高性能)**:
- 使用TCP Socket通信
- 实时数据传输，毫秒级响应
- 支持多客户端并发
- 推荐用于生产环境

**2. 文件模式 (兼容性)**:
- 保持原有文件轮询机制
- 用于向后兼容和故障恢复
- 性能较低，但可靠性高

**3. 自动模式 (智能)**:
- 自动选择最佳通信模式
- Socket优先，失败时降级到文件模式
- 自动恢复尝试Socket连接
- 推荐用于需要高可用性的场景

## 6. 错误处理与故障排除

### 6.1 常见错误及解决方案

| 错误现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 连接被拒绝 | 服务未启动 | 启动AI服务: `python ai_service_integrated.py` |
| Socket超时 | 网络问题/服务过载 | 检查网络，增加`SOCKET_TIMEOUT` |
| JSON解析错误 | 数据格式错误 | 检查请求数据格式，启用调试日志 |
| 模式切换频繁 | Socket不稳定 | 检查网络连接，调整`AUTO_SWITCH_THRESHOLD` |
| 性能下降 | 高并发压力 | 增加`MAX_CONCURRENT_CONNECTIONS` |

### 6.2 监控与日志

**日志位置**:
- `logs/error_log_YYYYMMDD.json`: 结构化错误日志
- 控制台输出: 实时状态和错误信息
- EA日志文件: MT5平台日志

**关键监控指标**:
1. **成功率**: 应保持在99%以上
2. **平均响应时间**: 应小于100ms
3. **模式切换次数**: 频繁切换表明网络不稳定
4. **错误类型分布**: 识别系统瓶颈

### 6.3 故障转移流程

```
检测Socket失败 → 记录错误 → 重试机制 →
达到重试阈值 → 触发故障转移 → 切换到文件模式 →
定期尝试恢复 → Socket恢复成功 → 切换回Socket模式
```
