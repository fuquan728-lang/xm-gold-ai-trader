# MT5 AI交易系统 - 系统架构

## 🏗️ 整体架构

MT5 AI交易系统采用**微服务架构**，分为三大核心模块：

```
┌─────────────────────────────────────────────────────────────┐
│                    MT5 AI交易系统 V3.0                       │
├─────────────────────────────────────────────────────────────┤
│  [MQL5 EA] ↔ [Python AI服务] ↔ [Web监控仪表盘] ↔ [数据库]     │
└─────────────────────────────────────────────────────────────┘
```

## 📦 核心模块

### 1. MQL5 EA模块（客户端）
- **位置**: `MQL5/Experts/`
- **主要文件**: 
  - `AI_Trader_Integrated_Socket.mq5` - 主EA程序
  - `socket_test.mq5` - Socket测试脚本
- **功能**:
  - 市场数据采集与预处理
  - 多模式通信（Socket/File/Auto）
  - 交易执行与风险管理
  - 实时面板显示

### 2. Python AI服务模块（服务器端）
- **位置**: 项目根目录
- **主要文件**:
  - `mt5_ai_service.py` - 主服务程序
  - `config.py` - 配置管理
  - `core/` - 核心功能模块
- **功能**:
  - 四模式通信服务（WebSocket/Socket/File/Auto）
  - DeepSeek AI集成与市场分析
  - 高性能缓存与连接池
  - 健康检查与监控

### 3. Web监控仪表盘
- **位置**: `core/web_dashboard.py`
- **访问地址**: `http://127.0.0.1:8000`
- **功能**:
  - 实时交易监控
  - 系统状态显示
  - 性能指标可视化
  - 历史记录查询

### 4. 数据库模块
- **位置**: `data/trading.db`
- **技术**: SQLite + SQLAlchemy
- **功能**:
  - 交易记录存储
  - 性能指标持久化
  - 系统状态备份

## 🔗 通信架构

### 四模式通信系统

```
┌─────────────┐    ┌──────────────────────┐    ┌─────────────┐
│   MT5 EA    │────│  Python AI服务       │────│  DeepSeek   │
└─────────────┘    └──────────────────────┘    └─────────────┘
       │                     │                         │
       ├─ Socket (TCP)       ├─ WebSocket              │
       ├─ File (JSON)        ├─ HTTP API               │
       └─ Auto (智能切换)    └─ 多协议支持             │
```

#### 模式详情：
1. **WebSocket模式**（V3.0新增）
   - 双向实时通信
   - 最低延迟
   - 自动重连机制

2. **Socket模式**（TCP）
   - 高性能单向通信
   - 连接池优化
   - 故障自动转移

3. **File模式**（兼容模式）
   - 基于文件系统的通信
   - 最高稳定性
   - 无需网络配置

4. **Auto模式**（智能模式）
   - 自动检测最优通信方式
   - 故障自动降级
   - 智能恢复

## 🔄 数据流架构

### 典型请求处理流程
```
1. MT5 EA采集市场数据
2. 通过选定的通信模式发送请求
3. Python服务接收并预处理数据
4. 检查缓存中是否有相似请求
5. 调用DeepSeek API进行AI分析
6. 解析AI响应并生成交易建议
7. 通过原通信模式返回响应
8. EA接收并执行交易决策
9. 记录交易结果到数据库
10. 更新Web监控仪表盘
```
